# 18+ 内容过滤说明

本文说明当前版本成人内容过滤的默认状态、临时关闭方式、匹配规则和适用范围。实现位于 `src/main/services/settings.ts`、`src/renderer/src/pages/Settings.tsx`、`src/renderer/src/store/useApp.ts`、`src/renderer/src/pages/Search.tsx` 和 `src/renderer/src/utils/normalize.ts`。

## 行为概览

| 项目 | 当前行为 |
| --- | --- |
| 默认状态 | 开启 |
| 是否保存关闭状态 | 否，仅保存在当前运行会话的前端状态中 |
| 临时关闭入口 | 设置页「反馈与关于」中的反馈输入框，输入 `4848` 后提交 |
| 恢复开启 | 完全退出并重新启动应用 |
| 过滤范围 | 搜索结果与分类浏览结果 |
| 搜索结果显示时机 | 关键词聚合搜索的所有目标站点完成后统一显示 |

## 默认开启与设置保存

成人过滤在主进程设置默认值中为 `true`。读取设置时，`getSettings()` 会把 `filterAdult` 强制设为 `true`；如果持久化数据中的值不是 `true`，会将修正后的设置写回。保存其它设置时，`saveSettings()` 也会再次强制 `filterAdult: true`。因此，通过普通设置保存流程无法持久关闭成人过滤。

渲染进程的 `AppState` 另有 `sessionFilterAdult` 会话覆盖值，初始为 `null`。搜索页按以下优先级确定实际状态：

```ts
sessionFilterAdult ?? settings.filterAdult ?? true
```

会话值为 `false` 时，本次运行暂时关闭过滤；会话值为 `null` 时回退到设置值，最终默认开启。

## 临时关闭方式

1. 打开设置页的「反馈与关于」选项卡。
2. 在「反馈建议」文本框中输入 `4848`，然后提交。
3. 页面显示“18+ 内容过滤已关闭，退出软件后将恢复开启”。

处理逻辑先对输入执行 `trim()`，再与字符串 `4848` 做完全相等比较。因此前后空白会被忽略，其他字符或额外内容不会触发该命令。命中后，程序调用 `setSessionFilterAdult(false)` 并清空输入框，然后直接返回；这条路径不会把口令保存到反馈记录，也不会发送反馈。

该关闭状态只存在于 Zustand 的应用内存状态，不写入设置文件或浏览器本地存储。当前界面没有重新开启的命令；退出应用并重新启动后，会话状态重新初始化为 `null`，持久设置仍为 `true`，过滤随即恢复开启。

`4848` 是打包前端代码中的固定字符串，只是隐藏操作入口，不是安全认证或访问控制。它不应被用来保护数据或限制恶意用户。

## 内容识别规则

直接识别规则定义在 `normalize.ts`：

```regex
/(伦理片|理论片|伦理|情色|成人|限制级|18\s*\+)/i
```

规则不区分英文字母大小写，并在片名和资源站分类名中作子串匹配。`18\s*\+` 允许数字 `18` 与加号之间出现零个或多个空白字符。规则覆盖：

- `伦理片`
- `理论片`（用于识别部分资源站采用的伦理内容分类，例如“理论片”）
- `伦理`
- `情色`
- `成人`
- `限制级`
- `18+`、`18 +` 等数字与加号之间带空格的形式

它检查两处元数据：影片标题 `vod_name` 和分类标签 `type_name`。苹果 CMS 数据会在主进程转换时把 `vod_class`、`vod_type_name`、`type` 等常见字段映射到 `type_name`。网页规则站若没有返回分类字段，仍可通过片名命中；如果资源站没有在标题或分类中留下可识别标记，单靠当前规则无法判断其内容属性。

## 跨站标题识别

只检查当前条目的标题和分类会漏掉“一个资源站标了伦理分类、另一个资源站用普通标题收录同一作品”的情况。搜索页因此会对本轮收到的所有站点结果执行两步处理：

1. `collectAdultTitleKeys()` 找出标题或分类命中直接规则的条目，并为其标题生成归一化键。
2. `matchesAdultContent()` 过滤每个站点的条目：直接规则命中、归一化标题与成人标题键完全相同，或者标题与本次搜索关键词满足代码中的相关子串条件，都会被过滤。

标题键由 `posterMatchKeys()` 和 `normalizeName()` 生成。归一化会处理全角 ASCII、大小写和标点差异，移除常见清晰度、语言、全集等采集站噪声，并去掉不影响作品身份的尾部别名；季数、部数等身份信息会保留。生成的标题键至少需要两个字符。关键词相关匹配也要求归一化关键词至少两个字符，并要求成人标题键和候选标题都与关键词存在包含关系。

这些规则以站点提供的标题和分类字段为依据，不会检查视频画面或播放地址。宽泛的标记词（例如“伦理”或“成人”）按子串规则匹配，可能将含有这些词但实际不属于成人内容的条目一并隐藏；归一化及关键词关联匹配也可能带来误判。

## 搜索呈现与超时

关键词搜索期间，主进程会逐站发送进度和结果，前端状态也会逐步更新。但搜索页在聚合搜索仍运行时暂不显示搜索卡片，等搜索 Promise 完成后，再用全部目标站点的结果计算成人标题集合并显示过滤后的结果。这样，被较晚返回的站点标为成人内容的同名结果，不会先短暂出现在关键词搜索列表中再消失。

有缓存的站点结果会直接计为已完成；请求失败的站点也会返回失败结果并计为完成。单站等待截止时间按站点有效超时计算，并限制在 10 至 30 秒之间；超过截止时间时该站点以失败结果结束本轮聚合。因而“统一显示”等待的是本轮目标站点均成功、失败或超时结束，不代表每个站点都一定有可显示结果。

分类浏览复用相同的成人识别与跨站过滤函数，但每个站点的分类结果是逐步加载的，代码没有套用关键词搜索的全站点等待门槛。分类浏览中，后续站点返回新的成人标题标记时，先前已显示的相关条目仍可能被重新过滤。

## 适用范围与边界

- 当前调用过滤逻辑的是搜索页中的关键词聚合结果和分类浏览结果。
- 首页推荐、详情页、收藏、观看历史和播放器没有经过这套成人内容过滤逻辑；不能据此认为这些页面也会隐藏相同条目。
- 搜索服务的站点结果缓存保存的是站点返回数据，成人过滤在渲染搜索页时执行。因此缓存命中仍会按当前会话开关重新计算显示结果。
- 当前没有成人条目专属计数；搜索页可见的“已挡掉”计数对应解说内容过滤，不能用作成人条目数量。

## 相关实现位置

- `src/main/services/settings.ts`：默认设置、读取时强制开启、保存时强制开启。
- `src/renderer/src/pages/Settings.tsx`：反馈输入框中的 `4848` 临时关闭入口。
- `src/renderer/src/store/useApp.ts`：会话覆盖状态与搜索/分类聚合结果过滤。
- `src/renderer/src/pages/Search.tsx`：会话状态优先级、跨站标题收集、过滤和关键词搜索等待显示。
- `src/renderer/src/utils/normalize.ts`：正则、标题归一化键和跨站匹配规则。
- `src/main/services/search.ts`：搜索站点完成、失败处理和单站等待截止时间。
