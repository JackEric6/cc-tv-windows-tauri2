丛丛影视 Windows 桌面版：功能与架构说明
========================================

文档用途
--------
本文记录当前仓库实际采用的技术结构、主要模块和用户可见功能。此前文件描述
的是已废弃的 Electron 原型，不能作为当前实现或开发入口的依据。

项目概况
--------
应用名称：丛丛影视 Windows 桌面版
技术栈：Tauri 2、Rust 宿主、WebView2 Evergreen、React、TypeScript、Vite
前端包管理：npm，锁文件为 package-lock.json
本地服务：Node.js sidecar，使用随应用打包的 node.exe 启动 dist/backend.cjs
安装包：Windows NSIS 安装程序
绿色版：安装程序静默安装到临时目录后打包应用文件；不包含卸载器和 ICO 文件
版本号来源：package.json、src-tauri/Cargo.toml、src-tauri/tauri.conf.json

当前目录结构
------------
src/
  main/services/       Node sidecar 服务：配置、站点、搜索、详情、解析、更新、存储等
  preload/             Node 后端与共享 IPC 类型
  renderer/            React 页面、组件、播放器和界面样式
  shared/              前后端共享类型、IPC 定义及搜索策略
  tauri/               Tauri 平台能力与 IPC 后端适配
src-tauri/
  src/lib.rs            Rust 窗口宿主和少量平台级命令
  resources/            sidecar 所需的运行时资源
  windows/              NSIS 安装钩子
  tauri.conf.json       Tauri 窗口、资源、图标与打包配置
scripts/
  build-tauri-sidecar.mjs  构建 Node 后端 bundle
  selftest.mjs             本地桩驱动的集成自检
docs/                    项目文档
release/<版本>/          已发布的安装包与绿色版压缩包

启动与调用关系
--------------
1. Tauri 启动 Windows 桌面窗口并加载 Vite 构建的 Web 前端。
2. Rust 宿主通过 sidecar 管理能力启动打包的 Node.js 与 dist/backend.cjs。
3. 前端通过统一的 window.api 接口发起配置、搜索、播放、存储和更新操作。
4. IPC 适配层把调用交给 Tauri invoke 或 Node 后端；网络请求、配置解析与文件
   持久化主要在 Node 服务侧完成。
5. 视频媒体在 WebView2 页面中的 Video.js 播放器内播放。

主要模块
--------
配置与站点
  config.ts 负责导入、校验、合并和刷新 TVBox 风格配置。
  sites.ts、congcongSources.ts 管理站点数据、内置来源和特定来源适配。
  配置、设置、收藏、历史等应用数据保存在应用数据目录；便携版本使用自身数据目录。

搜索与浏览
  search.ts 执行多个站点的搜索请求并逐源返回结果。
  category.ts 负责分类树、分类列表和分页。
  detail.ts 负责影片详情以及播放线路、剧集解析。
  搜索源显示顺序由共享搜索策略维护；站点超时和失败按单源处理，避免单个源长期
  阻塞整体结果。

播放
  renderer/src/pages/Player.tsx 负责选集、线路、进度、弹幕、播放历史和预览帧。
  renderer/src/utils/videojs.ts 封装 Video.js 播放器初始化与媒体 seek。
  主播放画面只由主播放器绘制；低分辨率预览帧只显示在进度预览小窗，不覆盖主画面。
  连续稳定播放 30 秒后启动全片扫描，先每 20 秒取帧，初轮完成后每 10 秒补扫。
  预览帧压缩为 160×90 JPEG，并保存在 WebView2 本地 IndexedDB 中。缓存按站点、影片、
  线路、集数及播放地址区分；同一内容再次播放时先读取已有帧，再继续补充扫描。
  播放器内部按住左右键时视频继续播放，进度条和已播放时间连续显示键盘移动目标；松开后
  seek 到最终位置并继续原播放状态。操作反馈按时长显示秒、分秒或时分秒。

直播与解析
  live.ts 负责直播列表解析和频道播放信息。
  resolve.ts、parse.ts 负责直链、解析接口和播放页嗅探等播放地址处理。
  http.ts 提供 sidecar 网络请求、请求头、代理和超时等共享能力。

数据与应用功能
  store.ts 使用 JSON 文件保存设置、配置、收藏和观看历史。
  updater.ts 查询 GitHub Release，按当前分支所需的安装包文件名筛选版本，测速下载链路，
  校验 SHA-256，并支持 Range 分段下载和链路失败后的切换。
  Rust 宿主负责窗口级能力；前端设置页提供更新、反馈、主题和播放器选项。
  系统托盘允许隐藏和恢复窗口，并提供显式退出入口。

分支与发布资产
----------------
main：标准资产名，不带分支后缀；更新器匹配
  cc-tv-windows-tauri2-<版本>-setup.exe
feature/remove-adult-filter：移除 18+ 过滤的独立版本；资产带 -no-adult-filter 后缀，
  更新器只匹配该后缀安装包。
release：独立发布分支；资产带 -release 后缀，更新器只匹配该后缀安装包。
每个分支同时发布 setup.exe 安装包和 portable.zip 绿色版。版本号标签用于三个分支共用的
Release，工作流通过 asset_suffix 避免资产互相覆盖。

构建与验证
----------
npm ci
npm run typecheck
npm run build:win

GitHub Actions 工作流：.github/workflows/build-windows-tauri.yml
工作流构建 Windows 安装包、从安装包生成绿色版、确认绿色版不含 ICO 文件，并可将资产
上传到指定 Release。发布不同分支时需使用对应的 asset_suffix：空、no-adult-filter、release。

本地自检：npm run selftest
自检使用本地桩检查关键前后端行为；它不代替 Windows 实机播放、更新安装或 WebView2
环境验证。涉及媒体源的播放效果应在实际 Windows 客户端中确认。

维护约定
--------
修改应用版本时同步更新 package.json、package-lock.json、src-tauri/Cargo.toml、
src-tauri/tauri.conf.json 和更新器的版本回退值。
修改更新资产命名时，同时确认 updater.ts、Actions 工作流输入和 Release 文件名一致。
播放器预览缓存属于用户本机数据，不随安装包或绿色版分发；清理时不得删除用户数据目录。
本项目不内置影视内容，播放内容由配置的第三方服务提供。
